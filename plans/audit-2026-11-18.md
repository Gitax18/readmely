# Project audit · 2026-11-18

**Scope:** every tracked file after Phase 1 (merged) and Phase 2a step 1 (on `feat/auth-email`): the Go API, migrate command, migrations and queries, the Python AI service, the web app, Dockerfiles, Compose, Makefile, git hooks, CI, Dependabot, the approved 2a plan, the full git history, and the GitHub repository settings.
**Method:** file-by-file read; a full-history secret scan; a check of every path ever committed; a check of the GitHub settings and open Dependabot pull requests. Nothing was changed while auditing.
**Status:** Approved 2026-11-18 ("Fix now" items). Code fixes are on `fix/audit-2026-11-18`; the 2a amendments (F13–F16) wait for the 2a work.
**Verdict:** no secret has ever been committed and nothing is exploitable today, because nothing faces users yet. Three findings are serious enough to fix before more code lands on top of them: a design flaw in the approved 2a rate limits, destructive migrate commands that are allowed by default, and `main` having no protection. Two earlier follow-ups (B5, B6 from 2026-11-17) were only half done.

Decisions, as before: **Fix now** (before 2a step 2, on this branch), **Fix in 2a** (amend the 2a plan), **Fix later** (named phase), **Ignore** (with the reason).

## Fix now

| ID | Severity | Where | Problem | Fix |
|---|---|---|---|---|
| F1 | **High** | `internal/migrate/main.go` | **Destructive commands are allowed by default.** `down` and `reset` are refused only when `APP_ENV` is exactly `production`; an unset `APP_ENV`, `prod` or `staging` lets `reset` drop every table. `seed` also runs when `APP_ENV` is unset. The migrate image is what production will run, and a missing variable is the most likely mistake. | Allow-list: `down`, `reset` and `seed` need `APP_ENV` set explicitly to `development` or `test`; the Makefile passes `APP_ENV=development`. Tests for unset, `prod`, `staging`. |
| F2 | **High** | GitHub settings | **`main` is unprotected.** CI is not required, direct pushes and force pushes are possible. PR #9 was merged without a confirmed green `ci-ok` on its last commit. | Apply the protection agreed in Step 6 (PR required, `ci-ok` required, up to date, no force push or delete). It is your call; GitHub may refuse it for a private repo on the free plan, in which case make the repo public or accept the risk in writing. Also turn on "delete branch on merge". |
| F3 | Medium | `apps/web/src/app/page.tsx`, `status` | **The public home page amplifies load.** Every anonymous page view makes the API ping Postgres and Redis and call the AI service, which pings Postgres again; when anything is down each view also writes warning logs. Nothing caches or limits it, so a simple request loop loads every backend and fills the logs. | Cache the combined report in the API for 5 seconds with one in-flight refresh (singleflight). Test that 100 concurrent requests cause one probe round. |
| F4 | Medium | migrations (roles) | **No timeouts for the service roles.** A stuck transaction can hold the per-user credit lock or job row locks forever and stall the queue and ledger; one slow query can hold a pool connection indefinitely. | New migration: `statement_timeout`, `lock_timeout` and `idle_in_transaction_session_timeout` for `readmely_app` and `readmely_ai` in this database. Test that a long query is cancelled. |
| F5 | Medium | `credit_ledger` | **A ledger row can point at another user's job.** `credit_reserve` and inserts check only that the job exists. The jobs table already forbids this for projects (composite key); the ledger does not. | Composite foreign key `(job_id, user_id) → jobs (id, user_id)`, `ON DELETE SET NULL (job_id)`, plus `UNIQUE (id, user_id)` on jobs. Test with a cross-user reserve. No data exists yet, so this is cheapest now. |
| F6 | Medium | `.dockerignore` | **Nested `.env` files are not excluded.** The patterns match the repository root only, so `apps/web/.env.local` (the usual Next.js file) or `services/*/.env` would be sent to the build and copied into the web build stage, where Next.js reads them. | Use `**/.env` and `**/.env.*` (keeping `!**/.env.example`), and check it by building with a planted file. |
| F7 | Medium | `.github/dependabot.yml` | **Dependabot proposes runtime major upgrades.** Open PR #7 moves Python 3.13 → 3.15 and Node 24 → 26; PR #8 moves TypeScript 6 → 7 and ESLint 9 → 10. Merging them would silently break parity with `.python-version`, `engines` and the local toolchain. | Ignore semver-major updates for base images and toolchain (upgrades become deliberate plans). Close #7 and #8; let Dependabot reopen the safe minor updates. |
| F8 | Low | `httpx`, `security.py` | **Health probes fill the logs** (B6, never done): three containers log a `/healthz` line every 5 seconds. | Log `/healthz` at debug level in both services. |
| F9 | Low | `infra/docker-compose.yml`, Dependabot | **Data-store images are pinned by tag** (B5, half done): `redis:8.2-alpine` is a moving tag; `pgvector` and `rustfs` too. Dependabot does not watch the Compose file. | Pin by digest and add the `docker-compose` ecosystem to Dependabot. |
| F10 | Low | `.env.example`, `migrate roles` | **Known role passwords work.** Both service roles default to the same placeholder, which passes the 16-character rule. | `migrate roles` refuses the placeholder and refuses the two roles sharing one password. |
| F11 | Low | config (Go, Python, migrate) | **The services disagree on configuration rules.** The API and AI service accept `APP_ENV` `development` or `production`, migrate also knows `test`; the AI service accepts any non-whitespace token while Go accepts only letters, digits, `-`, `_`, so one value can start one service and not the other. | One rule set in both languages, with the same tests. |
| F12 | Low | migrations | **New functions are executable by everyone by default** (Postgres grants `EXECUTE` to `PUBLIC`). Harmless today; a future `SECURITY DEFINER` function would be exposed the moment it is created. | `ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC` in the F4 migration; grant explicitly. |

## Fix in 2a (amend `plans/phase-2a-email-login.md` before step 2)

| ID | Severity | Problem | Fix |
|---|---|---|---|
| F13 | **High** | **Per-IP rate limits break behind the same-origin rewrite.** With the approved `/api/*` rewrite every request reaches Go from the web server's address. "20 codes per IP per hour" becomes 20 for the whole site, so one person can lock everyone out of sign-in. If Go instead trusts `X-Forwarded-For` naively, an attacker sets any IP they like and the limit is gone. | The web server forwards the client address; Go trusts `X-Forwarded-For` only from the configured web proxy and takes the right-most address that proxy added, never the left-most. Tests: spoofed header ignored, one IP limited without affecting another, direct callers use the socket address. |
| F14 | Medium | **The rewrite must never reach the internal listener.** Both listeners have `/api/...`-style paths; pointing the rewrite at port 8081 would publish `/readyz` and the status detail. | Rewrite to the public listener only, configured separately from `API_INTERNAL_URL`; a browser test that `/api/readyz` and `/api/api/v1/status` return 404 through the web app. |
| F15 | Low | **Background email sending is unbounded.** "Send in the background, never awaited" means one goroutine per request and lost emails on shutdown. | A bounded queue with a few senders, drained within the shutdown timeout; overflow is logged and counted, and the response is unchanged (no enumeration). |
| F16 | Low | **`__Host-` cookies need a secure context.** Chromium and Firefox treat `http://127.0.0.1` as secure; Safari has not always done so, which would make local sign-in silently fail there. | Note it in the plan and the README; e2e runs on Chromium. If Safari matters locally, serve dev over HTTPS later. |

## Fix later

| ID | Severity | Phase | Problem | Fix |
|---|---|---|---|---|
| F17 | Medium | Phase 5 | **The money rule lives only in one function.** `readmely_app` can insert any ledger row directly, so an app bug or a stolen app credential can add a reserve without the balance check (negative balance) or mint credits. | Revoke `INSERT` on `credit_ledger` from the app; grants, settles and refunds become `SECURITY DEFINER` functions with a fixed `search_path`, like `credit_reserve`. |
| F18 | Medium | MVP release | **Migrations run as a Postgres superuser.** The image's `POSTGRES_USER` is a superuser; it bypasses every privilege, and default privileges belong to whoever runs the migrations. | A dedicated non-superuser owner in production; `migrate up` refuses a superuser when `APP_ENV=production`. Joins B1 (database TLS). |
| F19 | Medium | Phase 4 | **Everything on the `internal` network trusts everything else.** The internal listener has no auth, and Postgres and Redis are reachable from every container. The ingest sandbox will handle untrusted repositories. | The sandbox gets its own network with no route to Postgres, Redis, the internal listener or the AI service. Write it into the Phase 4 plan. |
| F20 | Low | MVP release | **Role passwords reach the server in plain text** (`ALTER ROLE ... PASSWORD`), so `log_statement = ddl` or a failing statement would log them. | Compute the SCRAM verifier in Go and send only that. |
| F21 | Low | Phase 3 | **Queue inputs are not bounded in SQL:** a negative or huge lease or backoff is accepted, and replaying an idempotency key with a different kind or payload silently returns the original (the ledger raises `CR002` for the same mistake). | Validate in the worker API; return a conflict on a mismatched replay. |
| F22 | Low | MVP release | **`api healthcheck` always probes 127.0.0.1,** so binding `HTTP_ADDR` to one non-loopback address makes the container unhealthy. | Probe the configured host when it is not a wildcard. |
| F23 | Low | MVP release | **Repository hygiene:** merged branches are not deleted and the unused wiki is enabled. | Turn both off with F2. |

## Checked and fine

The full history has no secret (gitleaks) and no sensitive file was ever committed (`.env`, keys, `ACHIEVEMENTS.md`, `session-id.txt`). Every Go and Python error path hides values; connection strings are never echoed; service tokens never follow redirects; request bodies are capped in both services; CSP is nonce-based with no `unsafe-inline`; images are non-root, read-only, capability-free and digest-pinned; CI uses a read-only token, SHA-pinned actions and checksum-verified downloads; the schema, privilege, ledger and queue guarantees all have tests that were proven by planted faults.
